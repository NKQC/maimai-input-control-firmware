# CapSense Cp tuning completion across PSoC, RP2040, Host, and UI

This change completes the Cp measurement path from the PSoC ISR/main-loop state machine through the RP2040 dual-core SPI mailbox and five-byte Host response to the Rust/Slint UI. It hides partially updated channel arrays, makes Host ACK wait for an actual PSoC SPI ACK, and version-gates UI state across connection and channel changes. Script changes propagate native exit codes, derive the embedded PSoC version from `main.c`, and build both Rust binaries. No blocker or high-severity defect was found, so the change can proceed to hardware flashing acceptance.

**Watch for:** **[Medium, confirmed]** a 100 ms RP2040 mailbox timeout returns failure without cancelling the queued command, so the PSoC can still begin measuring after Host has received NAK; **[Low, confirmed]** the changed Cp state and timeout path have compile coverage but no Cp-focused selftest or 0.4.9 hardware result.

## High-level view

The PSoC changes `pending` to `active` in one critical section and returns zero from `GET_CP` while either flag is set. The result array starts at `0xFFFFFF`, is reset before each pass, and becomes visible only after all 36 channels and scan-mode restoration complete.

The RP2040 submits `MEASURE_CP` with a non-null output pointer to select synchronous mailbox completion. FIFO ownership keeps the slot safe, but timeout means “result unknown,” not “operation cancelled”; the current Host NAK collapses those meanings.

Host compatibility remains channel plus little-endian `u32`, exactly five payload bytes. The PSoC value is 24-bit, so the fifth byte remains zero while Rust continues to enforce the established five-byte shape.

`CpPollState` clears on disconnect/reconnect, gates values per channel, polls every 500 ms, and stops active measurement after 10 seconds. `ParamEditorRow` sends the SpinBox’s live value for “apply all.”

`dev.ps1` preserves native exit codes while trimming output and derives the embedded version from PSoC source. `main_firmware/build.ps1` now uses `--locked --bins` so both UI and selftest are built.

## PSoC publishes one complete Cp generation

`SENSOR_CMD_MEASURE_CP` sets `measure_cp_pending` and installs the SPI ACK (`psoc_firmware/CY8C4147AZI-SensorCore/main.c:433-436`). The main loop atomically changes `pending=true, active=false` into `pending=false, active=true` (`main.c:527-536`), initializes all channels to failure, performs the 36 BIST measurements, restores the current scan mode, and clears active in a second critical section (`main.c:540-567`). `GET_CP` returns zero throughout pending/active (`main.c:439-443`), while startup initializes every channel to `0xFFFFFF` (`main.c:477-482`). A second command during an active pass remains pending for one subsequent full pass; no transition exposes the array while it is being rewritten.

## RP2040 ACK wait cannot cancel timeout

`Psoc::measure_cp` passes an output address into `_submit`, selecting blocking completion (`main_firmware/src/protocol/psoc/psoc.cpp:252-256`). Core1 executes `_spi.measure_cp()` and validates the PSoC response before publishing `done`, so Host ACK no longer means only “queued on RP2040.”

**[Medium, confirmed]** The wait exits after 100 ms at `psoc.cpp:198-200` without removing or cancelling the command. Core1 may consume it after core0 returns false and `SensorLink` emits `SENSOR_ERROR` NAK. The ring slot itself remains safe because the consumer retains tail ownership until execution finishes, but the Host can observe failure followed by fresh Cp results from that same request.

## Five-byte Host response remains compatible

`SensorLink` emits `[channel, cp byte 0, byte 1, byte 2, byte 3]` with payload length five (`main_firmware/src/service/sensor_link/sensor_link.cpp:339-346`). Rust requires five bytes and decodes little-endian `u32` (`control_software/src/proto/telemetry.rs:311-320`). Pending `0`, failure `0x00FFFFFF`, and successful fF values therefore preserve the existing Host frame shape.

## CpPollState and ParamEditorRow use current-session values

Connection and disconnect edges reset polling versions/state, while connection and channel changes request fresh params and Cp (`control_software/src/main.rs:393-476`). Measurement first reads at 500 ms, repeats every 500 ms, accepts only responses newer than the request and measurement/channel cutoffs, and terminates at 10 seconds (`main.rs:286-306`, `478-527`). Zero maps to “测量中,” `0x00FFFFFF` to failure, and other values to fF. `ParamEditorRow` reads `param_value.value` directly for apply-all (`control_software/ui/app.slint:494-515`), avoiding stale Rust model values after editing.

## Build wrappers leave hardware behavior unverified

`Invoke-NativeTail` captures `$LASTEXITCODE` and exits with it after output trimming (`dev.ps1:35-62`). `Get-PsocVersionHex` parses the source defines and supplies the converter (`dev.ps1:64-79`, `194-207`). The full workflow derives the same version and invokes Cargo with `build --locked --bins` (`main_firmware/build.ps1:57-78`, `305-319`).

**[Low, confirmed]** `control_software/src/bin/selftest.rs` has no Cp measurement/get path, and this review performed no flashing. The first 0.4.9 hardware acceptance must cover the protocol states and UI lifecycle rather than relying on compilation.
