# Scan restoration can report success before device confirmation

The final review finds one remaining blocker in the noise-spectrum state machine: it treats successful admission to the Host transmit queue as successful device restoration. A deferred PARAM_SET or final baseline-reset failure therefore leaves the channel changed while the UI removes the scan lock and reports that the original settings were restored. Watch for: **confirmed** scan cancellation or normal completion can falsely claim restored gain/divider and baseline after a device NAK or transmit timeout.

## High-level view

The sweep keeps CSD mutual exclusion only while `NoiseSweep.active` is true, but the restoration sequence clears that flag immediately after queueing its final baseline reset. The queue reports a later device failure through generic ACK/NAK handling rather than back to the sweep, so no state remains that can retain the lock, retry, or change the completed status. **confirmed**

## Spectrum restoration loses ownership before the device accepts it

`debug_param_now` returns `Ok` after placing a PARAM_SET on the shared queue and optimistically changes the local cache; it does not wait for the device reply (`control_software/src/app_state/mod.rs:2817-2827`). `_sweep_restore` chains two such writes with calibration, then queues the final baseline reset. It only observes queue-admission errors, immediately clears `noise_sweep.active`, and emits the “original values restored and recalibrated” status (`control_software/src/app_state/ch_ops.rs:1120-1176`). A subsequent PARAM_SET NAK can therefore make a heat-map cell represent the prior gain/divider, and a later restoration NAK leaves the physical channel unrecovered after the UI has lifted the sweep guard.

The normal NAK path only clears an operation when its sequence matches `op_wait_seq`; it does not feed a restore result back into `NoiseSweep` (`control_software/src/app_state/mod.rs:7039-7048`). The same asynchronous gap exists in configuration of each scan point, so a failed gain/divider write is not marked invalid before RAW collection. Add a sweep-owned pending-sequence phase for configuration and restoration, including an explicit failure terminal state. The completion message and `active = false` transition must follow device ACKs for both restored parameters, calibration, and baseline reset (or a readback confirmation), while NAK/timeout must preserve a visible recovery-required state. **confirmed**

</details>
