**Verdict**: APPROVED

## High-level view

全局校准、基线复位和频率搜索的 UI 入口进入同一个 36 通道 Host 队列，每个通道只在上一条真实终态和冷却窗口结算后推进；固件的 `0xFF` 全通道分支仅作为兼容和内部恢复入口保留。

批量计划通过 `global()` 冻结 IDAC 起点，未保存草稿与 Cp 偏向使用同一份值。旧同步 AUTO_TUNE 响应先比较当前请求 seq，迟到响应不能再收割下一通道。

CALIBRATE 和 BASELINE_RESET 只有在 core1 等到 PSoC `busy` 落下后才由 SensorLink 生成 ACK。等待环持续喂看门狗并泵 TinyUSB，但不递归调用命令分发；Host 仍按原 seq 将终态交给批次或频谱状态机。

单通道校准、自适应和基线收尾只恢复目标 `widgetContext` 和目标基线，不再执行全局初始化。实机仍需验证电气侧隔离、GND/High-Z、分辨率量程和缺帧恢复；缺少刷写记录本身不改变静态批准结论。

## CALIBRATE/BASELINE 终态贯通到 Host 队列

`Psoc::calibrate` 与 `baseline_reset` 现在传入非空完成槽和 50 秒预算，`_submit` 等待 core1 写回 `c.done/c.ok` 后才返回（`main_firmware/src/protocol/psoc/psoc.cpp:355-420`, `main_firmware/src/protocol/psoc/psoc.cpp:467-475`）。core1 的 `PsocSpi::_wait_op_done` 轮询 PSoC `GET_STATS.busy` 到零，SensorLink 再按返回值生成 ACK 或 NAK（`main_firmware/src/protocol/psoc/psoc_spi.cpp:301-346`, `main_firmware/src/protocol/psoc/psoc_spi.cpp:434-447`, `main_firmware/src/service/sensor_link/sensor_link.cpp:590-612`）。

```text
Host seq N -> RP -> core1 -> PSoC busy=1 -> target operation -> busy=0
           <-                 c.done/c.ok                 <- ACK/NAK seq N
```

Host 只在 ACK/NAK seq 等于 `op_wait_seq` 时把结果归给 `ChBatch`/`SweepApply` 并解锁，批量推进还要求 `inflight` 清空且 `_csd_locked()` 为假（`control_software/src/app_state/mod.rs:6939-6965`, `control_software/src/app_state/mod.rs:7180-7197`, `control_software/src/app_state/ch_ops.rs:880-958`）。等待期间持续执行 `watchdog_update()` 与 TinyUSB task（`main_firmware/src/protocol/psoc/psoc.cpp:377-413`）；命令解析只在主循环的 `UsbComm::update()` 执行（`main_firmware/src/main.cpp:405-408`），等待环不会递归进入同一 SensorLink handler。

## 草稿 IDAC 与 AUTO_TUNE 请求归属

批量计划和 Cp 偏向预览都从草稿优先的 `global(GPARAM_IDAC_GAIN_INIT)` 取起点档（`control_software/src/app_state/ch_ops.rs:649-654`, `control_software/src/app_state/ch_ops.rs:697-702`）；该 accessor 先查 `ConfigDrafts`，再回退设备缓存（`control_software/src/app_state/mod.rs:3610-3616`）。编辑全局 IDAC 后直接寻找频率时，36 个 Prime 和 Cp 推导不会再使用旧设备值。

旧同步 AUTO_TUNE 响应在解析 payload 或清状态前要求 `auto_tune_req_seq == frame.seq`（`control_software/src/app_state/mod.rs:5793-5806`）。新推送流继续以 `origin_seq` 做同一门控并将终态归入当前批量通道（`control_software/src/app_state/mod.rs:5820-5851`, `control_software/src/app_state/mod.rs:5890-5962`）。

## 目标 widget 恢复不再触碰其他通道

`_idac_lock_restore(target)` 在单通道时只遍历目标 `widgetContext`，全通道哨兵才遍历全部锁定项，且不调用全局初始化入口（`psoc_firmware/CY8C4147AZI-SensorCore/main.c:432-458`）。校准只执行目标 widget 的校准、IDAC 恢复和 `Cy_CapSense_InitializeWidgetBaseline`；基线命令按 `baseline_ch` 选择单 widget 或全量分支，AUTO_TUNE 单通道收尾采用同样的目标恢复（`psoc_firmware/CY8C4147AZI-SensorCore/main.c:1831-1892`, `psoc_firmware/CY8C4147AZI-SensorCore/main.c:1920-1944`）。

目标在耗时操作前复制到局部变量，全局目标槽随即恢复为 `SENSOR_CH_ALL`；后续 SPI ISR 不能覆盖当前操作的恢复目标。`g_op_busy` 也只在所有 pending 标志清空后落零（`psoc_firmware/CY8C4147AZI-SensorCore/main.c:1837-1844`, `psoc_firmware/CY8C4147AZI-SensorCore/main.c:1948-1956`）。
